Трекер расходов — конспект по коду

FastAPI и Uvicorn
FastAPI связывает адреса с методами Python. Например, запись
self.app.get("/api/expenses")(self.get_expenses) означает «когда придёт
GET-запрос на /api/expenses, вызови get_expenses». GET читает расходы,
а POST на тот же адрес добавляет расход и возвращает его номер.

Uvicorn запускает сервер, принимает запросы и передаёт их FastAPI.
Команда из папки проекта: python3 -m uvicorn main:app --port 8765
Здесь main — файл main.py, а app — приложение, созданное в конце файла.
При GET / вызывается метод index. Именно там TemplateResponse обращается
к файлу static/index.html.

Как сохраняется расход
1. При POST /expenses метод submit_expense получает данные формы.
   В записи «expense: Expense = Form()» слово expense — имя параметра,
   Expense — модель для проверки полей, а Form() указывает их источник.
2. Модель проверяет сумму и дату. Field(gt=0, decimal_places=2, ...)
   требует положительную сумму с точностью до копейки. Decimal позволяет
   работать с десятичной суммой точно: 125,50 рубля × 100 = 12550 копеек.
3. Метод add_expense проверяет категорию. Выражение «not in CATEGORIES»
   означает «такого кода нет в словаре». Тогда raise прерывает метод,
   а FastAPI возвращает ошибку 422. Иначе INSERT добавляет строку в SQLite.
   Значения для :kopeyki, :category, :day и :comment передаются отдельно
   от текста SQL. Поэтому кавычки внутри комментария сохраняются как текст.
   cursor.lastrowid даёт номер только что добавленной строки.
4. После записи submit_expense возвращает код 303. Браузер заново открывает
   главную страницу через GET. Обновление страницы не повторяет добавление.

Как работает контекстный менеджер database()
Контекстный менеджер задаёт, что сделать при входе в блок with и при выходе
из него. Разберём один вызов «with database() as db» по шагам.

1. @contextmanager позволяет использовать функцию database() внутри with.
   При входе sqlite3.connect(DATABASE) открывает соединение с базой.
2. Строка «yield connection» передаёт соединение вызывающему коду под
   именем db. Функция database() в этот момент приостанавливается.
3. Внутри блока можно выполнить, например, db.execute(...) для записи расхода.
4. При выходе управление возвращается в database(). В строке
   «with closing(...) as connection, connection» действуют два менеджера.
   Правый, connection, подтверждает изменения при успехе или отменяет их
   при исключении. Затем closing закрывает соединение. Это срабатывает
   и при return из блока, поэтому возвращать номер расхода внутри with можно.

При загрузке main.py этот же менеджер используется для создания таблицы.
BEGIN IMMEDIATE заранее занимает право записи. CREATE TABLE IF NOT EXISTS
создаёт expenses, только если такой таблицы ещё нет.

Как читать короткие записи Python
• [dict(row) for row in ...] — пройти по строкам запроса, превратить каждую
  в словарь и собрать список. row_factory = sqlite3.Row позволяет обращаться
  к полям по имени. SQL сортирует строки по дате, а при равных датах — по id.
  DESC означает порядок от большего к меньшему.
• sum(row["kopeyki"] for row in rows) — взять сумму в копейках из каждой
  строки и сложить. Например, 2500 и 1050 дадут 3550 копеек.
• **self.get_expenses() — добавить в текущий словарь сразу оба поля
  результата: entries (список расходов) и total_kopeyki (общая сумма).
• day: date | None = None — можно передать дату или пропустить её.
  В выражении day or date.today() при отсутствии даты берётся сегодняшняя.
• urlencode(...) собирает параметры для адреса, а f"/?{query}" подставляет
  готовую строку параметров вместо {query}.

Категории расходов
В categories.py запись «class Groceries(ExpenseCategory)» означает, что
Groceries наследует общий класс категории. Каждый дочерний класс задаёт
свои code и title. Запись {category.code: category.title for category in ...}
перебирает классы и собирает словарь. Например, по ключу "groceries"
можно найти название «Продукты».
